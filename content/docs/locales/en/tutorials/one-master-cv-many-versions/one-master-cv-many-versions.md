# One master CV, many tailored versions

**The simplest way to apply for different roles is to keep one complete master CV and select from it for each application, instead of copying and editing files.** In OpenCiVera the master CV is your private **Experience Base**, and each application gets its own **LiveCV version**.

## Why copies drift

When every application gets its own copy of the CV, the copies diverge. A new achievement lands in one file and not in the others, and after a few months you no longer know which file is current. The cure is one source of truth plus selections of it.

## How it works in OpenCiVera

- **The Experience Base** holds everything: all employers, projects, courses and skills, in every language you maintain. It is never public.
- **A LiveCV version** is a saved selection: which summary, which experiences, which skills. A backend-developer version and a team-lead version can come from the same record.
- **Language versions** are kept in step, so a Polish and an English CV of the same experience do not drift apart.
- **Publishing** is separate from editing. Each version has its own [LiveCV link](/docs/tutorials/publish-and-share-cv), and editing the Experience Base does not change a published one.

## A practical routine

1. Add every new achievement to the Experience Base once.
2. When you apply, [create a LiveCV version](/docs/tutorials/create-cv-version) and select what fits the role.
3. Publish it, or download a [PDF or ATS file](/docs/tutorials/export-pdf-and-ats) for portals that want an upload.
4. Name versions by role or company so you can find them later.

If you already have a CV, [import it](/docs/tutorials/master-resume-basics) instead of retyping it.
